# App Store Screenshots

A Next.js + ShadCN editor for generating App Store and Google Play marketing screenshots.

> **Note:** This app is 100% vibe coded using [Claude Code](https://claude.com/claude-code) — no line was hand-written. Expect the occasional rough edge.

## Origin

This project was originally generated by the
[`ParthJadhav/app-store-screenshots`](https://github.com/ParthJadhav/app-store-screenshots)
Claude Code skill as a per-project template. It has since been extracted
into its own repository — with full commit history preserved from where it
was originally generated (inside the `activity-log` repo) — and is now
hand-maintained here as a single tool shared across every project in this
workspace, rather than a template re-copied per project.

## Quick start

```bash
pnpm install   # or yarn / npm
pnpm dev       # http://localhost:3000
```

## Multi-project architecture

This tool is a single shared instance for every Flutter project in this
workspace — it does not hold any project's data itself. Each project's
config and screenshots live inside *that project's own repo*, in a
`screenshots-assets/` folder (e.g. `../activity-log/screenshots-assets/`).

- **`projects.json`** (this repo's root) is the registry: each entry has an
  `id`, display `name`, and a `root` path pointing at that project's asset
  folder. Add a project by adding one entry here — no code change needed.
- **The project picker** (top-left of the toolbar, shown when 2+ projects
  are registered) selects the active project. The choice is stored in the
  `?project=` URL query param (bookmarkable, and lets two tabs edit two
  projects independently) with `localStorage` only used to pick a default
  on a bare load.
- **`/api/project`**, **`/api/upload`**, and **`/api/asset/<projectId>/...`**
  are all scoped by the active project id and read/write inside that
  project's own `screenshots-assets/` folder — never this repo.
  `/api/asset` exists because Next's static `public/` folder can only serve
  files inside this repo; per-project screenshots live outside it, so they're
  streamed through this dynamic route instead.

## What's inside

- **Connected canvas editor** (`src/components/editor/`) — every screen sits on one horizontal canvas, so phones, captions, and other elements can be dragged across screen boundaries and exported as split crops when Connected mode is enabled.
- **Screen controls** — drag-to-reorder screens, click-to-edit text, screenshot drop targets, per-screen layout switcher, dark/light toggle.
- **Device frames** (`src/components/editor/device-frames.tsx`) — iPhone (PNG mockup), iPad, Android phone, Android tablet (portrait + landscape), Mac (bare screenshot).
- **Store banners** — Google Play's feature graphic and App Store Connect's product page header and search results images share one "banner" layout (icon, name, headline and subtitle beside two devices), fitted to each asset's layout box (`BANNER_LAYOUT_BOX` in `src/lib/constants.ts`: full height, middle 84% of the width for Apple's assets). Apple's stricter template safe area (`BANNER_SAFE_AREA`), which survives even featured-placement crops, shows as a dashed outline in the editor only. Apple banners export as PNGs without an alpha channel (`src/lib/opaque-png.ts`): App Store Connect rejects banners with alpha, its asset library rejects JPEG banners, and browsers always add alpha to canvas PNGs.
- **Auto-save (git-trackable)** — every change is persisted within ~600ms to the active project's own **`app-store-screenshots.json`** (via `/api/project?project=<id>`) **and** mirrored to a project-namespaced `localStorage` key as an instant-paint cache. Commit that file (inside the project's repo, not this one) and you can `git clone` to another machine and resume exactly where you left off.
- **Multi-device decks** — iOS, Android, and Mac slide decks live side by side; switching the platform tab preserves all of them.
- **Reskin-only tenants** (white-label support, e.g. Pro IQ) — a project can define `tenants` in its JSON with per-tenant accent/background color overrides and a `{tenant}` screenshot-path token. Headlines/layout stay identical across tenants; only colors and screenshots vary. The tenant dropdown only appears for projects that define more than one tenant.
- **One-click export** — bulk PNG export at any required App Store / Play Store resolution using `html-to-image`; each PNG is rendered from the current connected or isolated deck mode.
- **Project migration** — older `app-store-screenshots.json` files are migrated on load. Existing per-slide transforms remain valid, and connected crops become available without rewriting the deck by hand.
- **Legacy-safe mode** — pre-v2 projects opened directly in the editor start in isolated-screen mode first, then can opt into connected crops with the toolbar's Connected/Isolated control.

## Adding screenshots

All paths below are relative to the active project's own
`screenshots-assets/` folder (in that project's repo), not this one.

Two ways:

1. **Drop a file in the inspector** — drag-and-drop or click Pick. The file is sent to `/api/upload?project=<id>`, hashed, and written to `<project>/screenshots/uploaded/<hash>.png`. The slide stores the resulting project-relative path, so commit those files alongside `app-store-screenshots.json` in the project's own repo and the screenshots survive a `git clone`.
2. **Reference a static file** — put PNGs under `<project>/screenshots/{platform}/{device}/{locale}/` (add `{tenant}` too for white-label projects) and reference them by that relative path. Default sample slides expect:
   - `screenshots/apple/iphone/en/...`
   - `screenshots/android/phone/en/...`
   - `screenshots/apple/ipad/en/...`

Update the matching `screenshot` fields in the project's `app-store-screenshots.json` to point at whatever filenames you choose.

## Exporting

The toolbar dropdown lists every Apple/Google-required size for the current device — including macOS's four required 16:10 sizes (2880×1800, 2560×1600, 1440×900, 1280×800). Click **Export bundle** to download a zip. In Connected mode, each PNG is clipped from the connected canvas, so an element that straddles two screens appears split exactly where you placed it. In Isolated mode, each screen clips its own elements and legacy offscreen content cannot leak into neighboring exports.

## Customizing

| Where | What |
|-------|------|
| `projects.json` | Registry of projects the picker offers, and where each one's assets live on disk |
| `src/lib/constants.ts` | Canvas dimensions, export sizes, frame ratios, shared starter theme presets, locales, tenant color merging |
| `<project>/app-store-screenshots.json` | Per-project starter state: app name, current device, connected-canvas mode, slide copy, screenshots, tenants, transforms, and (usually) an inline `theme` — lives in that project's own repo |
| `src/lib/defaults.ts` | Fallback/reset state used when no project file or local cache exists |
| `src/components/editor/slide-canvas.tsx` | Add new layouts and connected-canvas element rendering |
| `src/components/editor/device-frames.tsx` | Tweak device chrome (bezel radii, camera dots) |
| `src/app/layout.tsx` | Swap the font (`next/font/google`) |

## Notes

- `mockup.png` is the iPhone bezel overlay, bundled with this tool (`public/mockup.png`) and shared across every project — it is not per-project data. Replacing it requires re-measuring the `PHONE_SCREEN` constants.
- Image preloading converts every resolved asset path to a base64 data URI before exports run, and export retries paths that were previously missing — this prevents the html-to-image race where some slide screenshots come out black.
- Reset via the toolbar's circular arrow icon clears in-memory state and reloads the default screens. To wipe disk state too, delete the active project's `app-store-screenshots.json`.
- **Persistence model** — the canonical state lives in the active project's own `app-store-screenshots.json` (git-tracked in that project's repo). On load, the editor reads a project-namespaced localStorage key first for instant paint, then overwrites with the file contents if present; if the file endpoint is unavailable, autosave is blocked so stale cache cannot overwrite disk. On save, both are written. If you ever see a conflict, the file always wins.
- **Migration model** — schema v1 projects do not need a manual conversion. On first load, the editor upgrades localized text and transform records, writes `schemaVersion: 2`, preserves all existing screens, and keeps `connectedCanvas: false` so old offscreen/clipped elements export exactly as isolated screens. Turn on **Connected** in the toolbar when you want elements to cross screen edges.
- **Themes** — `src/lib/constants.ts`'s `THEMES` map only holds the generic starter presets (`clean-light`, `dark-bold`, `warm-editorial`, `ocean-fresh`, `bloom-roast`) a brand-new project can reference by `themeId`. A project with its own brand palette should define it inline instead, as a `theme` object on its `app-store-screenshots.json` (see `pro-iq` or `activity-log` for examples) — `theme` always wins over `themeId` when both are present, and it's the right place for anything project-specific rather than adding another entry to the shared `THEMES` map. The fallback-theme warning only fires when a project has neither a valid `themeId` nor an inline `theme`.
